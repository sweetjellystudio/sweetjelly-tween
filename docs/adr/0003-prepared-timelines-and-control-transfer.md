#   Prepared trajectories and replacement control executions

Status: accepted, 2026-11-08. The user confirmed Q1–Q7 and the final shared understanding. Existing serialized players remain the authoring surface; time sampling is an additional capability, rather than a change to Snap or a game-specific animation system.

A prepared timeline retains origins, easing, direction and composition. A control exclusively owns one execution of that trajectory. Transfer cancels the previous command/await and gives the control a new identity, so old cancellation tokens cannot stop manipulation. Keeping the original await alive was rejected because its cancellation ownership would follow into direct control. Sampling, including endpoints, never dispatches playback/game callbacks or completes the execution. Explicit automatic resumption completes at the selected endpoint and notifies only the root; disposal cancels while retaining the displayed pose. Restore and re-evaluation reuse the same capture until explicitly re-prepared.

Sequence sums captured child spans and Group takes their maximum. Live legacy playback has frame-quantized boundaries; transfer freezes observed cycle spans and held endpoints to preserve its actual pose without rewriting legacy scheduling. Idle preparation uses nominal spans. Same-property sequential children use calculated preceding values; simultaneous conflicts, shared player instances, cycles, mixed clocks/lanes/services and unsupported player capabilities are rejected. Only the three concrete consumer value players initially participate. Timing remains engine-independent; Unity targets/lifecycle stay in Framework.Unity and automatic control uses the existing scheduler.
